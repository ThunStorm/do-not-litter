# 数据目录配置与日志保留压缩实施计划

日期：2026-10-26（原计划）；2026-10-27已获授权并完成源码与隔离验证，归档用于设计追溯。实际能力、发布与未闭环项分别以当前实施状态和带日期生产快照为准；本正文中的“本次仅规划/未来授权”保留为原写作时边界，不再作为当前待办。生产根实际搬迁、物理故障和真实模型质量未验证。

## 1. 结论与必要性

有必要实施，范围应是“统一管理应用产生的数据 + 安全切换数据根目录 + 分类别的日志生命周期”。现有后端已有 `ZHIJIAN_DATA_DIR`，设置页已有日志保留天数，需补齐部署、历史路径、故障恢复和文件日志管理，避免再造互不一致的配置。

数据与代码分离便于换盘、容量管理、备份和升级；迁移时必须保障数据库、截图、上传文件及任务续跑引用一起有效。日志压缩可延长有限容量内的排障窗口，但不能替代容量上限、过期清理和敏感信息控制。

本次抽样：项目 `data/cache` 约 859 MiB、`permanent` 143 MiB、`logs` 53 MiB、`models` 141 MiB、`runtime` 281 MiB；数据库文件约 27.7 MiB，LaunchAgent 日志目录约 16 MiB。目录数值为 `du` 的占用口径，数据库为文件大小，非全盘盘点、非持续增长率；未据此判断磁盘紧张。建议作为运维完善工作实施，不必以紧急清盘方式处理。

## 3. 功能范围与验收目标

第一版提供一个用户可指定的**应用数据根目录**，覆盖本应用拥有的数据库、上传资料、截图/封面、缓存、音频、导出、模型资产、结构化运行日志和受控运行状态。普通用户不必为每类数据分别配置目录；外部模型库等既有显式路径作为例外列出来源与是否纳入迁移，避免静默改动其他软件资产。

应用源码、前端构建、Python/ASR 执行环境属于应用安装部分，维持独立。现有混在 `data/runtime` 的 Qwen venv 在迁移预检中识别为执行环境：保留并显式固定路径，或在安装目录按固定依赖重建；不能原样搬移后假定可用。执行环境重建纳入单独技术校验，不默认下载模型或执行真实 ASR。

完成条件：新指定目录成为 API、Worker、CLI、Alembic、部署管理和本地锁的同一来源；旧资料、截图、转录和续跑均可读，重启及重装服务后仍生效；目标盘失联不创建新空库；迁移可恢复。日志可以独立配置轮换、保留、压缩与容量，活跃文件和业务数据不被误删，压缩/清理有可查询结果。

不增加云存储、网络盘数据库、多根目录任意拼接、自动清理永久资料、全盘文件管理器或完整备份产品。第一版根目录仅支持经过权限/锁/原子操作验证的本机固定卷或可移动卷；网络共享、云同步目录及未验证文件系统不进入支持范围。

## 4. 统一路径与配置设计

### 4.1 启动配置的唯一来源

采用独立于代码仓库和数据根的、用户权限保护的启动配置，例如 `~/Library/Application Support/Zhijian/storage.json`（拟定位置）。记录当前根目录、实例 ID、卷/根目录标识、配置版本、迁移阶段和必要的旧根映射；不记录密钥和正文。原子写入，保留上一版，防止中断留下半份配置。

生产由部署管理读取该配置并为 API/Worker 渲染同一环境；配置代次和实际加载路径可只读查询。CLI/Alembic 使用同一解析器；显式测试/开发环境变量允许覆盖，但生产启动遇到环境与保存配置冲突必须报告并停止，不静默选一方。没有启动配置的旧安装首次采用原有效数据目录，不在升级时自动迁移。

启动前先确认已挂载卷身份、根目录实例标记、权限与数据库存在性，再打开日志/数据库。对既有实例，根目录或数据库丢失时失败退出，不能被 `ensure_directories` 或 SQLite 隐式建库掩盖。只有明确的新实例初始化流程可建立新库。

本地模型互斥锁、高德节流锁、模型队列锁必须使用同一解析结果，防止 API 与 Worker 落入两个根而突破串行/QPS限制。迁移维护锁应位于稳定的启动配置控制目录，在切根时也不失效。

### 4.2 目录分类

| 数据根下的位置 | 用途与默认规则 |
| --- | --- |
| `app.db` 及 SQLite 管理文件 | 业务库；保留兼容布局，禁止当日志压缩或删除 |
| `permanent/` | 用户上传、原始资料、截图/封面、导出等；按已有业务删除契约管理 |
| `cache/` | 可再生产物；引用/续跑有效期决定可清理性，不按目录名无条件删除 |
| `models/` | 应用拥有的模型权重；无自动过期，外部显式模型库另列 |
| `runtime/` | 运行状态/锁；执行环境与此分离，锁不作为可恢复的活跃执行状态复制 |
| `logs/active/`、`logs/archive/` | 应用运行日志；新布局由受控升级迁移，兼容读取旧 `logs/*.jsonl*` |
| `maintenance/` | 本实例容量扫描和生命周期摘要；不包含 Secret 或正文 |

操作系统临时文件、Keychain、第三方软件管理的模型缓存和启动配置不承诺全部落入根目录；设置页明确显示这些例外。启动控制的最小兜底日志保留在系统用户日志目录，使数据盘缺失时仍能诊断，其保留与轮换也纳入策略。应用主动生成的临时文件尽量显式指定受控目录；逐个核对外部进程的输出目录，避免“页面显示已迁移、子进程还写旧盘”。

### 4.3 新文件引用与历史兼容

新增受管文件引用采用根目录相对路径/受管 storage reference，由统一解析器还原；解析器规范化路径并拒绝 `..`、不受信符号链接和根外逃逸。用户显式导入的根外本地媒体只读引用应与应用拥有文件分开登记，迁移与清理不得误动原件。

历史绝对路径只在已登记旧根前缀、字段白名单和受管文件清单内映射到新根；不能全库字符串替换，也不能改写 Source 原始 locator、转写文字或 Evidence 中出现的路径。读、写、删除、下载和 Replay 都使用同一解析器，避免读取已映射而清理仍删旧路径。无法识别的历史引用进入迁移报告并阻止不完整切换。

若必要的引用结构/迁移状态需要数据库新字段或表，追加 Alembic migration，生产迁移另行授权；优先复用现有 JSON 和外部维护状态，但不以节省迁移为由破坏校验/审计。

## 5. 设置页与操作流程

设置增加“存储与日志”入口，复用现有界面组件。显示当前生效数据目录、拟切换目录、容量及更新时间、数据分类占用、例外路径、迁移状态和最近维护结果。目录是服务所在 Mac 的目录，手机/浏览器端通过路径输入与服务器预检操作，不能用浏览器下载目录或 File Picker 冒充服务器路径。

目录操作为“输入路径 → 预检 → 查看搬迁范围/空间/例外 → 保存待应用方案 → 在安全维护窗口执行 → 核验结果”。保存草稿不切换运行中的数据库。预检需检查绝对规范路径、可读写权限、可用空间、是否同一目录/相互嵌套、目标是否已有其他实例、卷身份及文件系统能力；写探针使用明确的临时文件并清除，不启动业务任务。

普通 HTTP 请求只保存方案/读取状态；耗时清点、哈希、复制进入后台维护流程。真正停服务和切根由稳定安装位置的本机维护协调器执行，不由即将被停止的 API/Worker 自己完成。第一阶段交付可用的本地管理命令和恢复机制，再接设置页；设置页不能以“保存成功”冒充已迁移。

如设置页支持发起应用，只能提交受保护的受限维护动作 ID 给本机协调器，不能传任意 shell 命令；沿用认证/权限保护。维护控制日志和状态位于稳定控制目录，服务不可用期间可从本机管理命令查看和恢复。操作展示预期短时不可用、未完成任务数量与下一步，不自动取消任务腾出窗口。

## 6. 安全搬迁与恢复协议

采用“复制并核验、原子切换、保留旧副本”，不以直接移动整个目录作为迁移算法。迁移不改变业务内容；如需规范化技术文件引用，保存可逆映射和修改清单。

1. **预检与登记**：记录迁移 ID、当前配置代次、源/目标卷标识、数据分类清单及预估空间；目标为专用空目录或经核验的同次迁移暂存目录，不合并其他实例。空间预算包含 DB/文件副本、临时压缩文件和余量；预复制大文件可缩短停机，但不能当一致性快照。
2. **排空与维护门禁**：停止接收新写任务，允许已排队/运行任务完成；等待模型测试、外部调用、租约及媒体进程为空，不中断任务。到安全窗口后禁用自动清理与所有业务写入，再停 API/Worker，并核对进程/文件句柄确已退出。协调器独立存活。
3. **一致性保存点**：建立经验证的 SQLite backup 与永久文件清单，处理 WAL 一致性并做完整性/FK 检查。不得在运行中只复制 `app.db` 丢弃 WAL，也不得将不一致的 DB/WAL/SHM 拼接。备份应位于不会被后续清理的保护位置，记录哈希和恢复方法。
4. **复制与重校验**：将受管数据复制至目标暂存目录；逐文件检查大小与哈希，核对 DB、图片/上传/Artifact 引用，以及模型权重权限。排除失效锁文件、进程 PID、临时 Cookie 等不应恢复的运行状态；执行环境和外部模型例外按预检方案处理。
5. **切换**：最终核对源配置代次未变化，提交目标实例标记和完整清单，原子更新启动配置并重渲染两个 LaunchAgent。API/Worker 先以维护只读模式启动，核对实际根目录/数据库身份/锁路径一致。
6. **验收后放行**：核对健康、Worker 心跳、资料/截图/转录读取、续跑有效性及日志新位置；完成后才开放业务写入。旧目录保留为只读恢复副本并在设置中列出，不能立即自动删除。
7. **失败恢复**：放行写入前可恢复旧配置和旧副本，记录失败阶段；应用新目录已有业务写入后不能直接回旧库，必须再次排空并同步/备份最新数据后恢复。迁移中断重启依据外部状态机和清单续接，避免两份目录分别写入。

旧副本删除作为独立显式维护动作，显示占用、可恢复性和备份状态，满足验收后执行；本包不设默认自动删除时间。维护门禁、压缩、清理和迁移共享协调锁，迁移期间不允许其他进程清掉正在复制的文件。

## 7. 日志保留与压缩策略

### 7.1 按类别设置，建议默认值

下表是拟实施默认值，不代表本次已生效。已有审计保留配置必须完整迁移，不能被新默认覆盖。

| 类别 | 拟定策略 | 边界 |
| --- | --- | --- |
| API/Worker JSONL | 单文件仍为 10 MiB；到大小或跨日封卷；关闭超过 48 小时的分卷 gzip；总保留 30 天；运行日志归档池默认上限 1 GiB | 30 天包含未压缩与压缩阶段；活跃文件不压缩，容量先到可缩短保留窗口，页面明确说明 |
| 旧式 stdout/stderr 与最小启动兜底日志 | 默认 7 天、每流 10 MiB 轮换，封卷超过 48 小时压缩；独立默认池上限 128 MiB | 不由普通 Worker 直接改名仍被 launchd 持有的文件，见下节 |
| 数据库系统事件/调用审计 | 保持现有默认 90 天、7–3650 天范围；后台分批过期清理 | 日志页查询继续查库；第一版不做自动数据库审计冷归档 |
| 转录、AI 缓存、媒体缓存、笔记/图片、业务记录 | 使用各自契约 | 不跟随日志设置清理；本包不改变转录 180 天及其他业务保留语义 |

文件日志设置包含：是否压缩、封卷压缩延迟、总保留天数、单卷大小、分类容量上限；校验取值及 `压缩延迟 < 总保留期`，不能配置零天导致意外清空。设置页说明“未压缩查阅窗口”“总保留窗口”“空间上限优先”及实际最早可用日志时间。容量超过阈值按最老封卷清理，不删除活跃日志、迁移保护文件或业务库；无可清理文件则告警。

缩短保留期/容量先提供影响预览，列出会过期的范围、数量和字节，再显式应用；不能刚保存草稿即删除。扩大保留期只影响仍存在的数据，界面不暗示能恢复已删日志。磁盘空间告警阈值可设置；低空间优先清理符合策略的封卷，不能擅自牺牲业务数据或仍可续跑媒体。

### 7.2 轮换、压缩、清理的职责

API 和 Worker 各自负责自己的文件轮换，使用不可变且不重名的封卷名称，避免现有 `.1/.2` 重编号与后台压缩竞争。封卷以关闭并登记为准，不只看 mtime。Worker 维护任务负责压缩和过期/容量清理，持有维护锁，限制单批数量、I/O/CPU 和最长时间，迁移/高负载时暂停并保留待办。

gzip 写入同目录临时文件，关闭后执行解压完整性及原始内容哈希检查，原子改名并更新索引后才删除原分卷。磁盘满、权限失败、进程中断时保留原文件，临时文件按登记状态清理；重试幂等，不能重复统计或重复归档。索引记录来源服务、时间范围、原始/压缩字节、校验哈希与策略版本，不记录日志正文。

日龄按封卷登记的 UTC 时间/可信内容时间范围计算，展示用北京时间；不靠复制后改变的 mtime 判断过期。独立策略更新需要配置版本，API/Worker 报告加载代次；热更新安全项即时生效，需要重开 handler 的项采用受控重新打开或维护重载，不显示虚假“已全部生效”。

### 7.3 LaunchAgent 日志必须处理文件句柄

第一版将应用捕获到的结构化日志归入新日志目录；未捕获 stdout/stderr 由安装位置的轻量本机日志包装器接管并负责关闭/重开轮换文件，launchd 只保留有界最小启动兜底输出。包装器正确转发退出码/信号、不缓冲到耗尽内存，应用子进程崩溃仍可记录。

包装器引入前，旧 stdout/stderr 仅在服务安全停止且句柄关闭时归档，禁止直接 rename 后继续假定 launchd 已切到新文件，也不把可能丢行的 copytruncate 当无损方案。此阶段若无法验证可靠轮换，就保留旧方式并将启动日志轮换列为未完成，不能宣称全日志已覆盖。

### 7.4 数据库清理与归档边界

现有 `data_retention_days` 内部键可兼容保留，前端名称细化为“系统事件与调用审计保留天数”。清理按批进行，事务可恢复，不阻塞主业务；活跃执行及必要续跑依赖记录需保护并显示延期清理原因。清理结果记录删行数和覆盖时间，不输出敏感内容。

删行不等于数据库文件立即缩小，面板分别展示逻辑可回收空间和磁盘占用。第一版不自动对在线数据库执行完整 VACUUM；需要回收时给出安全维护步骤，检查空间/备份和无活跃写入门禁。不能 gzip 在线数据库以实现日志压缩。

若以后需要长于在线保留期的审计冷档，另开工作包设计脱敏导出、归档索引、查询/恢复及最终到期清理；冷档不能成为无限保留历史的后门。本包的压缩交付以文件日志为边界。

## 8. 其他数据的清理保护

缓存扫描仅统计和识别可清理候选；应用前重查 Job/Artifact 租约、打开文件、有效续跑窗口及共享引用。未知归属/仍被引用的文件不删，失败或不完整下载可在安全期后按登记记录清理。路径解析必须保证只删除本实例受管文件，旧绝对路径不能指向用户原始媒体或其他目录。

转录保留沿用 180 天契约，并在实施时核对 raw/corrected、Evidence 引文及中间产物的一致性，发现缺口记录为明确验收阻塞/关联修复，不把“日志功能通过”当作全部数据生命周期正确。保留期不自动扩展到永久笔记和截图，备份/旧迁移副本的生命周期单独披露，不能承诺已从所有副本物理清除。

Secret 继续使用 Keychain；开发 FileSecretStore 不放入日志归档，若授权搬迁保持目录/文件权限。临时 Cookie 仅在任务需要时创建，完成或失败后按既有安全流程删除，不纳入长期迁移副本。所有扫描/日志导出沿用脱敏，路径清单只对授权管理用户可见。

## 10. 验收矩阵

| 场景 | 必须证明 |

| 外置卷缺失、同路径被其他卷占用、实例标记缺失 | 停止正常启动，保留可读诊断；不在空挂载点自动建新库 |
| 有排队/运行/模型测试/租约/外部调用 | 等待安全窗口，不为搬迁中断任务，不发生跨根并行本地推理 |

| 旧缓存路径、共享媒体、根外文件、符号链接逃逸 | 只处理受管且可清理文件；仍有效引用/用户原件不删 |
| 压缩中断/磁盘满/损坏 gzip/多维护实例/轮换竞争 | 原卷完整、压缩校验有效、操作幂等、无丢行/重复索引 |

| LaunchAgent 长期持有日志句柄、崩溃/重启 | 文件真正关闭并切换，启动错误仍可追溯，服务信号与退出码正确 |
| 日志清理、转录180天、永久笔记/图片和Keychain | 清理对象严格分开，不改业务保留政策，不导出密钥 |
| 设置 PC 约1192px / Mobile390px | 服务端路径说明清楚，预检/保存待应用/执行状态/失败反馈可用，无溢出和相关错误 |

目标测试先覆盖配置/路径解析、迁移状态机、日志完整性及保留边界，使用临时目录/隔离 DB/伪造时钟/子进程故障注入；不通过真实 Provider、ASR、视频重跑测试存储功能。代码包结束后一次全量后端/前端及 Lint、类型、构建；新失败/改动再补相关检查。真实外置卷拔插与进程重启仅在隔离实例和授权范围验证，不能模拟结果冒充物理故障测试。

生产验收需要明确的目标目录与搬迁授权，并满足活跃任务、备份、完整性门禁。只读核对实际服务配置/加载根、静态资源、数据库身份、图片/转录与日志新写入；执行一次授权可逆本地样本验证存取。没有生产搬迁时只能交付“功能已实现、隔离验收通过”，不得写成“生产已迁移”。
