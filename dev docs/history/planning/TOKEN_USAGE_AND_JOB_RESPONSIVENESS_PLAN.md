# Token 用量与任务响应优化计划

日期：2026-10-08；状态：已完成并归档；2026-10-09 纳入当前分支的文档与远程交付工作包。范围：缺省 Token 的本地估算与展示、取消响应、超时重试与 ASR 活动提示。先实施离线验证，再按闲置门禁无迁移部署，最后更新当前状态与交接。

## 验收条件

1. 上游可信 Token 优先；输入和输出分别判断，缺省时沿用已有本地字符估算（约 2 字符/Token），标明“估算”，不冒充账单或精确 tokenizer。未返回输出的失败/取消调用仍为未知，不补造输出。
2. 保留 API 原实测计数字段，添加估算与未知计数；历史审计只读推导，不回填。任务页在缺省时显示估算或未知，不再把缺省显示为 0；Cache hit 不重复计消耗。
3. 估算参与现有预算；取消/失败的已发起请求输入纳入保守估算，不因缺失 usage 绕过预算。未发起的请求不计真实调用。
4. 在请求等待、重试间隔和 ASR 子进程运行期间可观察取消；旧执行结果仍受 run fence 门禁保护，不允许旧执行与重跑并发物化。停止客户端不等于上游已停止消费。
5. 模型超时不继续重复同一请求；允许的备用路由仍受原策略、能力和预算门禁约束。ASR 补充等待活动，不伪造处理百分比，普通无活动 watchdog 仍有效。
6. “以原配置重跑”及配置冻结契约保持。PC/390px Browser、目标测试与一次完整前后端验证通过；部署前无活跃 Job/lease、完整性与逻辑备份通过，部署后 API/Worker/心跳和实际用量 HTTP 返回验证通过。

## 工作包

- P1：统一用量解析与本地估算，审计/预算复用；汇总增加估算、未知字段；任务页和测试覆盖可信 0、未知、部分 usage、历史行、Cache 与失败输出。
- P2：补齐可取消等待与 ASR 子进程清理，保留取消信号；收敛超时重试，增加离线取消/超时/活动回归。
- P3：构建与 Browser 验收、无迁移备份重载、HTTP/服务验证；更新专项契约、IMPLEMENTATION_STATUS 和 CURRENT_HANDOFF，归档完成计划。

## 边界

不改提交时配置或历史业务结果；不执行真实 Provider 测试、不重跑视频、不自动确认 POI、不迁移数据库、不提交或推送。仓库已有其他工作区改动原样保留；部署加载当前 checkout，必须先确认无活跃任务。精确 Token 与上游取消效果仍需真实接口证据，本轮不以估算或离线测试替代。
