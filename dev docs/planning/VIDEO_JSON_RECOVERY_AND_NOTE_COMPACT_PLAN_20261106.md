# 视频 JSON 截断识别与归纳精简计划

2026-11-06。范围为 GROUND_MAP 截断分流、NOTE_REDUCE 输出及离线和真实样本验收。发布沿用现有 SQLite 0027、同一模型和路由。真实对照在隔离库复用 BV1Hrxe6YEbQ 已存转写、逐字证据和上一轮请求。输入预算仍为 4000。共用账号串行，真实对照最多发送两次首答，每个选定包使用既有纠错门禁且总实际尝试最多四次。原视频、源证据、POI 状态、Note 版本和线上业务表保持原样。

| 步骤 | 实施内容 | 通过条件 |
| --- | --- | --- |
| 1. 冻结基线 | 用 LocalAiMux 请求 ID 和至简审计哈希绑定五份原响应，记录原始错误、包和运行参数。保留证据在本地既有库。 | 五份哈希一致，能区分驼峰字段、根对象缺闭合符、引文中断及两份引号错误。 |
| 2. 按完整文本识别截断 | 在现有 JSON 对象提取前检查完整后缀。只有明确的未完成 JSON 才走现有输出截断分包。保留语法错误的同模型有界纠错和既有确定性修复。 | ②③走 `AI_PROVIDER_OUTPUT_TRUNCATED`，④⑤仍走 `AI_PROVIDER_INVALID_JSON`，①仍拒绝缺失 ID。完整对象、合法转义引文、围栏和已有可恢复输出兼容。无引文改写、丢失字段补造或无界重试。 |
| 3. 精简归纳输出 | 仅 NOTE_REDUCE 使用短输出契约。要点承担主要正文，`thesis` 可选；省略分包 `overview`、重复 `summary` 和 `body_markdown`。服务端保留对现有完整字段的兼容，使用原引用和包归属校验，缺失证据沿用原文回退。 | 原样保留 Segment ID、Mention ID、逐字引文、日期数字、否定与条件。保持原有分组、全局概览、主题溯源和 `HYBRID` 行为。Legacy 非 Map 总结继续使用原提示词。 |
| 4. 离线与真实验收 | 五份历史响应逐笔离线走新解析器和已有编译门禁。用目标回归覆盖实际截断分流、证据校验及省略正文字段。真实对照选原两份引号失败包，原证据不变，仅替换归纳契约。记录首答、重试、引用和估算用量。 | 离线五类结果符合预期。真实结果按包检查 ID、引文、关键事实与条件，分别记录首答和恢复结果。局部对照不外推整篇成功率、上游 Token 或费用。 |
| 5. 发布及交付 | 后端目标回归后执行一次完整验证。核对上次发布源、当前未提交改动、数据库修订、空闲任务及租约。建立源码及静态保存点和已验证 SQLite 备份，空闲后重载并检查 HTTP、Worker 心跳、静态哈希与业务表。只提交本包并推送当前远端分支。 | 已通过验证才发布。API/Worker READY，业务摘要一致，原笔记版本及阅读接口正常，远端提交与本地一致。出现偏差则按保存点回退。 |

驼峰别名和单个根闭合符的自动恢复留待单独评估。当前缺少证据证明放宽字段或接受未完整输出能安全提高事实覆盖。Qoder 的原生 JSON Schema 能力也单列，当前路由保持实际已验证的参数契约。历史错误只用作回归依据，原始请求及响应全文保留在本机。
