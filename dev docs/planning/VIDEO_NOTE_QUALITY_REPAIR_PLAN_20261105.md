# 视频笔记质量修复：实施与验收计划

日期为2026-11-05。本文件保留原实施方案，后续授权范围和实际结果以[实施与验收报告](../benchmark/NOTE_QUALITY_ACCEPTANCE_20261105.md)为准。

## 1. 目标、基线与范围

目标：将“重复地点、分块拼接和大量待核原文”修复为有据、紧凑、可回溯的地点攻略。保留真实疑点与负向限制，不以消除告警为质量目标，不增加默认模型阶段或逐地点第二次模型校验。

诊断样本：[适合十二月份的反向旅游目的地推荐](http://127.0.0.1:8787/video-notes/note_5d4ce16b1ba34f8d97fed7e740f18fea)，视频 BV1Hrxe6YEbQ，当前版本 `ntv_4d380c29c19e4b0faf0754f1eb30bb09`。2026-11-05再次只读核对：57段转写、6个内容单元、20个语义实体、43条Claims、20条地点候选/19个不同名称、22个阅读章节，其中21章含“作者意见或归纳待核对”。两条拉萨分别从05:27、05:35开始；告警记录13条证据要点未被模型章节完整覆盖。Note接口状态为COMPLETED，不能据此认定语义验收通过。以上为此版本基线，不代表其他笔记。

处理范围：作者态度校验与降级、跨包同地身份、主目的地/景点阅读组织、抽取与归纳覆盖、事实去重、摘要、篇级质量提示及对应回归。排除ASR引擎升级、地图重设计、Provider配置变更、自动POI确认、历史批量清洗。不得将本样本“五个目的地”硬编码为通用章节数量。

现有工作树已有Gateway、视频处理、API及文档等在途改动。实施前记录HEAD、相关文件哈希及可恢复快照；本计划涉及的video_support.py、grounded_map.py、video_notes.py等须按差异隔离，禁止覆盖、回滚或一并发布未核对的改动。

## 2. 先冻结的验收口径

| 维度 | 本样本通过标准 | 必须保留的边界 |
| --- | --- | --- |
| 地点身份 | 新生成结果中拉萨有一个有效逻辑身份，两个来源区间均可追溯 | 原始实体/旧版本不改写，同名异地不误并 |
| 阅读结构 | 河池、丙中洛、从江、拉萨、玉溪五个目的地主章；景点与体验进入对应子项，未归属限制单列 | 阅读从属不等于合并Place，也不建立无证据地理关系 |
| 可靠正文 | 已验证事实正常表达，单条态度疑点不清空整章；没有只有占位句的摘要或章节 | 存疑态度不得变成明确正向推荐 |
| 关键覆盖 | 人工标注的关键事实逐条覆盖，或逐条显式待核；关键限制不得静默遗漏 | “原文保留”不等于“归纳完成”；机器通过不等于全面语义正确 |
| 重复控制 | 同一事实正文只表达一次；独立条件、否定、数值和主体不因去重消失 | 原句、Segment、旧anchor、截图绑定和不连续source_ranges完整保留 |
| 质量披露 | 任务终态与内容质量分开；归纳缺口有篇级说明及可定位明细 | 不改COMPLETED/PARTIAL_SUCCESS状态机，不额外常态展示地点态度标签 |
| 成本与安全 | 离线阶段真实Provider/视频/POI调用为0；默认不增加模型阶段 | 4000输入预算等原配置、完整请求门禁、精确缓存、取消/时限/QPS规则保持 |

质量验收分三层记录：A=离线规则与证据链；B=API及PC/Mobile阅读；C=真实模型语义。A/B通过不得标为C通过。

## 3. WP0：建立可重复基线与人工答案表

输入：当前Note详情、places、transcript、screenshots和其已绑定GroundedMapArtifact；只读导出最小必要字段，删除凭据、环境配置和无关记录。记录采样时间、Note/Version/Artifact/Transcript身份、SHA-256及取数路径，不用“当前最新Artifact”替代版本实际绑定。

产物建议放 `backend/tests/fixtures/travel_pipeline/december_reverse_bv1hrxe6yebq/`：provenance.json、必要转写/语义产物/旧章节、golden_facts.json与golden_structure.json。真实原文与人工标注分开，模拟模型响应明确标为fixture。57段转写逐段检查；每条关键事实记录fact_id、主体、类型、原句、Segment IDs、数值/单位/时间、条件/否定、预期章节、是否需核对。

首批必验事实：河池枯水期水量下降、景区分散与元旦客流；丙中洛非自驾不便、丙察察普通轿车路况限制；从江梯田十二月灌水、节庆与客流；拉萨冬季不推荐自驾、景区费用表述与节日条件；玉溪上中旬建议、约25日前后开渔节、节庆价格/客流/可能没房及元旦增加。日期与价格均标“视频作者原述”，不推导为今年有效安排。

验收：答案表每条可回到逐字原文；两条拉萨的连续讲述关系和五个主章有证据；补充同名异地、跨主题重返同地、多人转述、整体不推荐、局部不推荐、共享片段、跨包断句、同片段切换地点等反例。基线测试能复现问题；无外部调用、无生产写入。

## 4. WP1：修复态度校验与过度降级（最高优先级）

落点：`recommendation_intent.py`的assess/mention_opinion，`video_support.py`的作者意见补充与unsafe章节替换。先用WP0样本和反例固定行为。

实施：
1. 保留逐字引文、主体、说话者、条件/时间校验；区分引文无效、归属不明、缺少整体推荐、真实正反冲突等原因。不得把所有NEEDS_REVIEW解释成整章事实不可信。
2. 正向措辞规则仅用于一致性检查；补上“适合某类人”“首选”等有证据表达的测试，不能靠命中“适合”就自动判定整体推荐。双重否定、转述、比较及条件限制继续保守。
3. 对只有LOCAL_DETAIL证据的景点，允许展示已核验局部看点，但不因此补造PLACE_OVERALL推荐。缺整体证据与局部事实无效分别处理；是否允许自动POI处理仍遵守原策略，不因阅读改善直接放行。
4. 用事实/陈述粒度处理降级：保留已验证天气、交通、费用和看点；无据的推荐结论去掉正向判断，展示具体疑点与对应原句；真实负向、CONFLICT及未知主体保持待核。无法安全拆分的混合句保留原句，不改写成肯定结论。
5. 条件归一化若只涉及空格/标点可确定性处理；跨段条件必须回到原文核验，保留原值与派生依据。不得为消除UNGROUNDED_CONTEXT而直接放宽校验。

验收：河池、丙中洛、玉溪中的可靠事实不再随态度疑点整章消失；“A值得去，但别坐游船”保持整体推荐与局部限制；“不建议去A”保留整体否定；无主体/无有效引文不升级推荐；疑点未解前自动POI调用0。新增测试进入 `test_recommendation_intent.py`、`test_poi_note_structure.py`；隔离生成结果只对问题结论标注，不反复插入同一句兜底提示。

## 5. WP2：跨包地点身份与阅读层级

落点：`grounded_map.py`的分包归并、`video_support.py`的候选合并、`note_structure.py`的organize_sections，以及详情/候选API。先解决身份，再做阅读归组。

实施：
1. 新Artifact增加有来源的逻辑身份/alias映射，原entity_id和content_unit_id仍保留。可先用既有JSON承载，具体字段与版本在实施时锁定；若确需数据库字段，必须新增迁移并另行授权，不能改历史迁移。
2. 同地候选须同时核对同Source/Snapshot/Transcript、名称或显式别名、地点类型、地域上下文、相邻内容连续性及无主题/主体冲突。地名相同或canonical_hint相同均不足以单独合并。拉萨边界断句可在离线归并阶段结合相邻合法证据核对；不得让模型引用本包外Segment。
3. 主章使用已验证内容单元主体或身份映射。AREA_GUIDE可以进入归组，但不得简单把所有AREA_GUIDE/EXPERIENCE改成PLACE_GUIDE；多主体比较、路线、未归属内容保持独立。
4. 根据显式内容单元/关系建立子项：河池下三门海等，丙中洛下怒江第一湾，拉萨下八廓街/大昭寺；从江的肇兴侗寨/加榜梯田、玉溪的抚仙湖/星云湖按有据内容呈现。不得仅凭同一Segment或地理常识广播事实。
5. 历史版本只读投影：来源足够时可调整目录层级和分组，保留原sections/markdown、所有旧anchor及截图关联；API不回写旧实体，也不伪装候选已经物理合并。无法核对的旧数据保持独立并说明。

验收：新结果拉萨一个有效逻辑候选、两个来源均保留；打乱包输入顺序不改变归并结果；同名异地、不同版本/提交、跨主题歧义不误并；主章按原视频出现顺序排列；五个主章的子项不形成新的重复一级章；所有旧anchor可定位、截图无丢失、不连续来源不扩大为连续证据。对历史API连续GET后核对相关业务行/哈希不变。

## 6. WP3：抽取与归纳两层关键事实覆盖

落点：`grounded_map.py`、对应语义抽取Prompt/Schema、`video_support.py`的map_facts与missing检查；先用WP0人工答案表检验召回，再修改最小必要链路。

实施：
1. 在既有抽取调用中明确保留交通、费用、日期、客流转折、限制和主要景点；转写含多个事实时允许多条Claim共用Segment，避免只抽推荐理由。不得增加默认全文复审或逐地点二次LLM。
2. 增加低成本风险提示：按内容单元核对未覆盖且含日期、金额、否定、客流/住宿变化等信号的原文片段。提示只表示“可能遗漏”，不能自动生成已验证事实。独立报告未检查的语义范围，不宣称关键词扫描保证完整召回。
3. 转写→Claims与Claims→笔记分别计量。第二层以主体、事实及引文/Segment身份核对；数值、单位、时间、否定、条件是必保字段，不能因共享Segment就认定已覆盖，也不能仅因引文措辞不同就重复追加。
4. 缺失事实在其所属主章下集中保留一次；多主体事实保留一条共同说明并引用，不向每个地点复制整段。统计明确区分“已归纳”“仅原文保留”“待核对”“未覆盖”。
5. 抚仙湖缺失实体须从现有原文重新抽取或有据物化为新版本产物；不得直接编辑旧Artifact。约25日前后的开渔节表述仍保留作者来源与时间不确定性，不产生当前活动日历。

验收：WP0关键事实召回、正确归属和必要限定保留均为100%；这个100%仅适用于人工答案表。每条未满足项输出fact_id和失败原因，不能用“HYBRID总体通过”掩盖。WP0所列限制均进入正确章或独立待核区；没有灌水期、没房风险等静默丢失；抚仙湖在新实体结果中有有效证据，既有弱证据不自动确认POI。

## 7. WP4：去重、摘要与篇级质量信息

落点：`note_structure.py`、`video_support.py`、`api/video_notes.py`、前端API类型及 `VideoNotesPage.tsx`。复用现有设计系统；新UI仅用于笔记质量和来源阅读。

实施：
1. 精确相同事实合并，长短重叠引文仅在主体、时间、条件和事实一致且长句完整涵盖短句时合并；相似文本不等同相同事实。费用区间变化、不同条件、修正意见或不同来源冲突不得吞并。
2. 合并保留全部evidence/Segment/原章节ID/截图关联。先整理可靠事实，再生成1—3句全局概览；本样本以五地差异、适合对象及主要出行限制为内容，不把21个待核提示拼成摘要。
3. API提供版本绑定的篇级quality_summary：至少包含note_version_id、assessment_version、状态、可核验的覆盖计数、问题分类及定位信息；这是拟新增契约，不声称已实现。首版不做迁移：纯函数根据该版本已存map_facts、sections、绑定Mention及Artifact计算可证明的项，缺少结构化依据的生成模式/仅原文计数等返回UNKNOWN/null，不借用Claim正文存质量元数据。逐条输出“已证实/未证实”，避免将无法区分归纳与原文兜底的内容计为归纳成功。
4. 当前generation_mode保存在Job payload，不能直接把“最新Job”当旧Note版本质量。首版生成模式只有存在明确note_version_id绑定时才引用，否则UNKNOWN。若需要永久保存完整结构化质量报告，单列WP4b：为AINoteVersion新增quality_report_json的追加式迁移、版本化读写和旧值NULL兼容；须在迁移授权后实施，不阻塞首版保守只读提示。历史数据不回填，不从中文warning中正则编造完整质量结论，默认GET不得重跑或写回。
5. 页面提供篇级“部分内容待核对/待归纳”说明与问题定位，正文优先显示可靠要点。细节可展开查看，但未解决的交通/住宿风险不可全部藏进折叠区。摘要字段与reading_overview的使用统一，旧字段保兼容。
6. 不新增常态地点态度标签，不更改原有整体不推荐标记规则；COMPLETED仍只表示已有产物，质量字段独立。缺质量字段的旧版本正常可读，不触发自动重跑。

验收：样本无重复占位摘要、无只有占位句的空壳章节；同一事实正文一次且多出处可达；问题计数口径有明确分母；UNKNOWN不显示“全部通过”；质量提示不把模型名、HYBRID等内部枚举直接当业务说明。PC 1440×1000、Mobile 390×844核验五主章目录、子项、跳转/旧anchor、来源展开、截图放大、质量提示和长文换行，无横向溢出及相关控制台错误。阅读/展开全过程不发写请求。

## 8. 分阶段执行、测试与停止条件

执行顺序：WP0 → WP1 → WP2 → WP3 → WP4。WP1/WP2先使结构与可靠正文可用；WP3解决内容缺口后，WP4才能输出可信摘要和统计。可分批验收，不把未完成工作伪装成完整修复。

目标测试优先扩展现有 `test_recommendation_intent.py`、`test_poi_note_structure.py`、`test_grounded_map.py`、`test_video_semantic_poi.py`、`VideoNotesPage.test.ts`；必要时新增专门的样本回归文件。禁止为了凑数量写只复述实现的测试。

| 验收组 | 必须覆盖 |
| --- | --- |
| 态度与事实隔离 | 正向表达、局部否定、整体否定、转述/双否定、引文错误、真假冲突、条件差异、零自动POI调用 |
| 身份与组织 | 跨包拉萨、同名异地、分包顺序、AREA_GUIDE/体验、多人/多地点共享片段、旧版本GET不写库 |
| 覆盖与去重 | 灌水/开渔节/没房风险、数值与否定、长短引文、多主体、遗漏显式保留、冲突不吞并 |
| 身份与安全 | Note/ntv/Artifact绑定、旧anchor与截图、raw/corrected边界、跨提交隔离、错误引用拒绝 |
| 预算与兼容 | 完整请求输入超限拆分、单条不可分零调用、精确缓存、取消/时限、主题来源与时节边界、旧API字段 |

开发中按改动跑目标测试；代码工作包完成后一次全量后端与前端验证。后端从仓库根使用 `PYTHONPATH=backend/src .venv/bin/python -m pytest -q backend/tests`，并跑 `.venv/bin/python -m ruff check backend/src backend/tests`。前端在隔离构建副本执行 `pnpm --dir frontend verify`（含ESLint、Vitest、TypeScript与构建）；不得覆盖线上静态目录。固定回归包含 `test_note_input_budget.py`、`test_note_theme_registry.py`、`test_title_temporal_evidence.py`、`test_yunnan_multiregion_travel_golden.py`，其中云南P0_CRITICAL不得回退。具体入口以实施时仓库配置为准。

停止/失败条件：出现误并主体、丢失负向/条件/引用、历史GET写回、自动真实调用、输入预算回退或跨版本错绑，立即阻止发布并修复；需要Schema/需求变更则单独说明，不偷偷扩大工作包。离线通过但真实模型未验，交付状态明确写“离线与页面通过，真实语义未验”。

## 9. 真实模型验收与成本对比（另行授权）

前置：A层全过、人工答案表确认、明确本轮模型/阶段/调用上限/Token预算和目标版本；串行共享Key调用，不改全局Provider设置。利用已存转写，只从能补齐缺口的最早必要阶段开始：本样本存在Claims/实体遗漏，仅重跑NOTE_REDUCE不足，至少需要重新生成受影响的语义抽取产物，再生成新Note版本；不因此重新下载媒体或运行ASR。

对照：同一已存转写、同一模型与有效参数、相同输入预算和来源证据，比较旧实现与候选。能复用已存真实基线时先披露其版本差异；条件不一致只作历史参照，不能声称严格A/B。若需要新基线调用，计入授权总额度。初次只做本视频，不默认扩张到全部历史视频。

记录：逻辑请求/实际尝试/缓存命中、输入输出Token、耗时、失败/拆分次数、可获得的费用；应用缓存与上游缓存分开，缺计费数据记UNKNOWN。优化目标为不新增常驻模型阶段、输入预算不扩大、相同人工答案表质量更好；总Token若增加，逐项说明来源，不用估算声称实测节省。
