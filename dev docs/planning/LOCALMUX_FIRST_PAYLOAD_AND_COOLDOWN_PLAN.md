# LocalAiMux 首包超时诊断与至简冷却续跑

2026-11-06 · 本期实施规格，M1/M2 源码与离线验证已完成。M1 改 LocalAiMux，M2 改至简 Worker；两者按同一接口契约验收。已发出请求的备用模型恢复另见[后续工作包](LOCALMUX_FIRST_PAYLOAD_FALLBACK_FOLLOWUP.md)。

## 依据与验收目标

11 月 6 日晚间（北京时间），「12月份最有氛围感的宝藏目的地推荐」第 1/5 块再次超时。Qoder CLI 日志显示上游已返回 HTTP 200，随后 120 秒未收到首个有效数据，报 `ModelFirstPayloadTimeoutError`。LocalAiMux #580 将它报成通用 502，并开启 30 秒连接冷却。「跨年去哪里最合适」随后复用前两块，第 3/4 块在 LocalAiMux #581 被冷却拦下，12 毫秒返回 503，零次上游调用，至简转为 `NEEDS_USER`。上游没有及时出首包的原因和该请求的实际用量未知。

离线验收复现 A → B：A 已发出并首包超时，日志明确标出超时层和时限。B 在冷却期内有一次本机拒绝、零次上游调用；Worker 释放 lease，到期后按原 Job 和阶段续跑一次，复用仍有效的成功分块。A 不因本期改动被自动重发。

## M1 · LocalAiMux 提供可判定的超时与冷却信息

- **首包超时。** 在 Qoder Adapter / CLI 正常输出的受支持错误事件上验证可见信号。只有明确识别首包超时，才复用 HTTP 504 / `LMX_PROCESS_TIMEOUT`，通过现有超时字段提供固定 `reason_code=upstream_first_payload_timeout`、对应的 `timeout_layer` 和有证据的 `timeout_limit_ms`（该样本为 120000）。Chat 与 Responses、流式与非流式以及调用审计的归因一致。CLI 已发出请求时，上游执行和取消状态仍为未知。通用退出、无结构错误和无法确认的 502 保留原分类。私有 CLI 日志可作人工取证，不能成为运行时依赖；避免持久化原始 stdout/stderr、提示词或凭据。
- **冷却。** `503 LMX_PROVIDER_COOLDOWN` 保留原状态与错误码。以同一次单调时钟读数计算连接实际剩余时间，`Retry-After` 取正整数秒并向上取整；冷却到期走原路由。仅在 Gateway 确认该请求尚未进入 Adapter 推理时返回 `upstream_dispatched=false`。同时给出白名单冷却原因，区分短暂连接失败、限流和额度（建议 `transient_failure`、`rate_limited`、`quota_exhausted`），让调用方不把长冷却尾段误判为短暂故障。路由前和等待连接锁后的冷却分支使用同一契约。
- **边界。** 保持每连接串行、启动间隔及现有熔断时长。LocalAiMux 只给出事实和等待提示；它不替客户端重发。队列等待 429、厂商限流、额度、鉴权与其他超时保留各自语义。若当前公开 CLI 输出不足以识别首包超时，单独记录该限制；冷却契约仍可交付。

实现入口为 LocalAiMux 的 `crates/adapters/qoder`、`crates/adapter-sdk/src/cli.rs`、`crates/router/src/lib.rs` 及 Gateway Chat/Responses 错误处理。更新 LocalAiMux 错误契约与变更记录。离线验证明确首包信号和未知失败、冷却剩余时间递减与到期放行、排队后再次命中冷却，断言拒绝分支未调用 Adapter。

## M2 · 至简 Worker 对短冷却延迟续跑一次

- **准入。** 本期只覆盖视频 `EXTRACT_TRAVEL_FACTS / GROUND_MAP`，初跑与手动续跑共用判断。仅受信的 LocalAiMux 配置返回上述 503、精确错误码、`upstream_dispatched=false`、`transient_failure`、可关联的请求 ID 和有效 `Retry-After` 时进入等待，当前连接失败窗口允许 1–30 秒。旧版 Mux、缺字段、超范围、任意 502/504、429、额度、鉴权和已经发往上游的请求沿用原错误路径。解析并白名单保留超时归因，通用错误不猜测原因。
- **排程。** 以原 Job ID 持久化最早恢复时刻、步骤、执行快照引用、来源请求 ID 和本轮一次性额度。用现有 Job payload 与续跑机制表达等待，Worker 领取前跳过未到期任务，允许处理其他 Job。保存等待状态、消费自动恢复额度、释放当前 lease 与记审计应原子完成；重启后按已保存时刻恢复，领取时获取新 fence。避免在 Worker 里持有 lease 睡眠，也避免用会重建配置或清空预算的人工重跑路径替代。记录可解释的“冷却待续跑”事件与预计恢复时间。
- **续跑与冲突。** 到期重新验证 Artifact、原执行快照及取消状态，复用符合原有完整缓存键的成功分块，保留上游已用预算和审计，不绕过输入、阶段和调用预算。区分网关拒绝记录与真实模型尝试，已发生的模型调用不因重新入队而漏计，确认未发出的拒绝不增加真实尝试数。一次性额度绑定原运行轮次，防止重复领取或重启后循环补发。等待中取消或人工重跑撤销旧计划；产物失效或再次冷却时停在可操作状态，保留原因，不自动从头重跑。

实现入口为 `backend/src/zhijian/ai/reliability.py`、`providers/llm.py`、`services/video_pipeline.py`、`services/job_replay.py`、`services/jobs.py` 与 Worker 领取逻辑。使用现有快照、lease/fence、Artifact 与审计，不引入新 Schema。补充专项契约和实际实施状态后再标记完成。

## 验证和发布顺序

| 场景 | 通过条件 |
|---|---|
| A 超时，B 随即命中冷却 | A 有一次真实发送和明确超时归因，B 有一次本机 503 审计、零上游调用 |
| B 等待与到期 | 到期前不领取且不占 lease，其他任务可执行；到期后仅安排一次，同一 Job，成功分块缓存命中，待完成分块按原预算执行 |
| 重启、取消、竞争与缓存失效 | 重启不丢等待或重置额度，重复领取和旧 fence 不生效，取消能拦住到期执行，失效产物不触发全量重跑 |
| 再次失败与版本交叉 | 第二次冷却不循环，已发送超时不补发；旧至简可忽略新增字段，新至简遇旧 Mux 保持现有处理 |

先做两仓各自目标测试，再用合成 CLI 和隔离 SQLite 做跨仓 A/B 故障序列，核对 Job、分块、调用 ID 与实际 Adapter 调用计数。代码交付前跑两仓规定的全量门禁。发布顺序为 LocalAiMux → 至简，先核对新增契约，再启用 Worker 消费逻辑。两个工作树都存在其他改动，发布从已核对的隔离快照构建，记录源码、二进制和回退点；停启前确认无活跃调用、Job 或 lease，按仓库发布规则完成备份与完整性检查。回退时先停用新版至简的自动恢复并处理待续跑状态，再回退 LocalAiMux。真实 Provider 请求、旧任务续跑和部署结果单独验收。


## 离线验证记录

真实回环 HTTP 将隔离 LocalAiMux、合成 Qoder CLI 与至简测试库连在一起。完成分块先执行一次，A 执行一次并返回 504、首包原因和 120000 毫秒。B 的 503 带剩余等待与未发出标记，合成 CLI 没收到 B。到期后至简换 lease 复用先前分块，合成 CLI 只收到一次 B。另有 SQLite 回归覆盖重新打开会话、等待期间可领取其他任务、取消、缓存或 Artifact 失效、前序真实调用预算和再次冷却。合成证据只证明本期契约和恢复行为；实机 Qoder 当次错误能否出现在 CLI 公开输出仍待独立确认。
