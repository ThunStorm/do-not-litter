# P｜POI 匹配准确性与复核数据契约

返回[总览](README.md)，遵循[执行契约](09_AGENT_EXECUTION.md)。承接原 02 WP0/WP1/WP3；原 WP2 UI 合入 U。本包后端为主，不以自动确认数量作为成功标准。

## 顺序与约束

1. **P1 原因分类。** 使用 G0 已裁定候选与已有响应；若近期 13+8 待核快照可得则纳入，不查询当前状态后假称当时快照。分类唯一可确认、多义、无结果、仅区域可定位、别名不明、证据不足、搜索错误、手工拒绝。输出 raw_name、有效行政上下文、查询/分页完整性、候选类别/分差、详情结果、规则拒绝原因及版本。用户已正确保守处理的 REVIEW 不当作 Bug。
2. **P2 反例驱动修复。** 原词保留，别名有证据；行政提示只来自同单元有效证据。景区本体、子景点、入口、游客中心和行政代表点分开；政府地址不能代替目的地。先复核现有分数/唯一性/详情/地域/意见门禁，不默认降阈值。确需阈值变化时须独立裁定与保留样本评估、误确认计数和分层错误分析；不是用小样本 ROC 图给新阈值背书。
3. **P3 可选分页与 DTO。** 只有满页导致有效候选缺失的反例才能加分页；先冻结单查询/单 Mention 的页数、候选数、总请求和墙钟上限，再实现。短页/满页不是独立的全集证明，结合 Provider 分页契约记录完整/部分/未知；429、取消、部分页面失败保持待核。共用缓存/QPS，不加逐候选 LLM。输出 U 所需原因码、证据引用、候选数据、revision/允许动作，展示文案由 U 维护。

## 验证与出口

入口 `services/video_support.py` 的 resolve_mentions_with_amap / 评分链、area_anchors、providers/amap、相关 API。目标测试 `test_poi_audit_regressions.py`、`test_poi_resolution_improvements.py`、`test_poi_resolution_benchmark.py`、`test_video_semantic_poi.py`。覆盖同名跨城、景区父子、区域代表点、负向/仅引用、满页空页、重复页、网络错误/429、并发 revision、运行中 Job、人工拒绝、隐藏、墓碑。

冻结已裁定样本内错误自动确认为 0，所有自动确认必须通过完整证据与唯一性门禁；同时列自动确认数和未裁定数量，不外推全量准确率。API 请求有界、缓存与取消可见；人工决定不被覆盖。离线隔离库可验证自动确认代码，不能据此运行生产确认。真实高德只读串行对照、实际确认、历史回写是不同授权；未授权全部 NOT_RUN。
