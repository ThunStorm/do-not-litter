# Agent 执行契约与派发模板

返回[总览](README.md)。本文件集中原七份 Plan 重复约束，避免各包规则漂移；不覆盖根 AGENTS 或用户当前授权。本轮只有文档工作，以下操作须未来明确选择实施包后执行。

## 接手与边界

先读 CODEX_CONTEXT → IMPLEMENTATION_STATUS → 相关冻结条目 → 所选包和一个相关专项；继续上次任务才读 CURRENT_HANDOFF 续接，部署才读生产段。不要每包强制加载所有交接/报告/大模块。记录 HEAD、工作树范围及现有未提交修改，必要时隔离工作树；不得重置/覆盖在途修复。每阶段先写目标反例、可改文件、输入输出/身份、验收与停止条件，再写代码。

默认单 Agent 串行执行；用户另行要求并行时，共享 video_support/router/video_pipeline 由唯一负责人集成，隔离分支不等于业务身份和 Provider QPS 已隔离。每次只做一个实现切片；后端契约先定，再做相应 UI。新计划不是修改冻结需求的授权。

原 07 的维护性工作随实际热点评估：先列至多 2–3 个可抽取切口，只有明确降低本次风险才选一个。提取纯函数与调整阈值/Prompt/状态机拆成独立差异；保持异常类型、公共入口、事务边界、缓存键、日志及路由等价，用特征回归验证，不凭行数目标拆模块。不需要就 NO_CHANGE；不把全面重构作为业务修复前置。CI 内容归 G0，不丢失原 07 的需求。

## 验证层次与发布

| 层次 | 方法与完成证据 | 不能外推为 |
| --- | --- | --- |
| 目标开发 | 最小反例、目标测试与 Lint/类型检查；Fixture/Mock 外部调用为零 | 模型质量改善 |
| 代码包收尾 | 后端全量+Ruff，前端 test/lint/类型/隔离构建各一次；新失败才重跑 | 生产已加载 |
| 真实业务 | 单独授权后配对样本、原始响应/配置/成本与人工裁定 | 全型号/全视频质量 |
| UI | 目标 PC/Mobile Browser：布局、交互、焦点、相关 console | 未覆盖页面正确 |
| 纯文档 | 链接、需求去向、manifest、生成一致性、diff 检查 | 任何业务实现 |

仓库已有入口为 `.venv/bin/pytest backend/tests`、`.venv/bin/ruff check backend/src backend/tests`；前端参考 `pnpm --dir frontend test` 与 `pnpm --dir frontend lint`，类型/构建按 package.json 和发布约定输出到隔离目录，不能覆盖正在提供服务的静态目录。先检查运行环境/锁定版本，不能为通过而换依赖或删测试。文档可运行 `.venv/bin/python scripts/test_build_complete_project_spec.py`。这些是执行入口，不是本次已运行记录。

前端明确实施请求已有持续发布授权：保存源码状态/可恢复工作树、备份线上静态资源与新旧哈希，隔离构建通过后发布；依赖 API 时核对生产版本/路由，无迁移且无活跃 Job/lease、数据库完整性和已验证逻辑备份满足后才按门禁重载。活跃任务不能为部署中断。发布后实际 HTTP 资源哈希、API/Worker 状态及生产受影响 PC/Mobile Browser 均核对，失败回退。阻塞则报告，不能将开发预览当生产验收；也不机械重复索要已有前端发布许可。

本计划不授予生产迁移、历史回填、真实 Provider/高德/ASR、媒体下载、POI 实际确认、视频重跑、提交或推送。实际前端发布之外的服务变更按相应授权处理。Schema 如确需新增则追加 migration，禁止改历史迁移；先说明必要性和兼容/回退。真实调用申请应给出固定输入/模型、次数与预算上限、串行/QPS、停止条件、历史副作用和证据保存位置。先完成不依赖该授权的部分；缺素材、人工裁定、决策和外部权限分别记录，不泛称“整个计划阻塞”。

## 交付表与停止条件

交付记录至少含：包/阶段、HEAD+工作树摘要、反例与根因、改动/NO_CHANGE、测试结果、Fixture/真实证据等级、基线/候选指标、样本数与未裁定数、额外调用和预算、Schema/依赖/历史影响、发布/回退证据、未验项及下一步一项。达到目标即停，不顺手扩展。

源码和自动验证更新 IMPLEMENTATION_STATUS；实际前端发布的生产采样记录写 CURRENT_HANDOFF 生产段。任务续接仅用户要求时覆盖更新、不新建交接；未复核生产保留旧日期并注明。新业务契约进入原专项，已覆盖旧计划只在确认无遗漏后归档。本计划中的源码快照不持续维护成第二份实施状态。
