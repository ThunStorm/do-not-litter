## 需要纠正或补全的逻辑

| 原表述/缺口 | 修订后的执行含义 |
| --- | --- |
| “7 份相互独立”，但金标、DTO 与共享文件交叉 | 标明硬依赖与条件依赖；默认串行，一个包一个切片；没有基线的模型调参不启动 |
| 一律先 01/03/02，06 放最后 | 输入错源会污染金标与质量判断，有复现时 S 升 P0，先纠正源头 |
| TP/FN/FP/NEEDS_REVIEW 并列 | 质量判定与处置状态是不同维度；unjudged 单列且报告裁定覆盖率 |
| “不漏报也不多报”作为不限定的总目标 | 冻结裁定样本内关键错误硬门禁，其他质量用明确分母与保留样本报告；不承诺开放世界零误差 |
| 金标错误自动确认 0 | 保留安全门槛，同时报告自动确认数、N/A 和未知项；自动确认全为 0 不证明匹配能力好 |
| 修改阈值要 ROC | 默认不改；小样本 ROC 不足以支持阈值，要求分层误差、保留样本与裁定证据 |
| 章节标题由地点/区域主导 | 保留合理主题/比较章；无地点证据时不能为了格式造地名 |
| 有证据或 NEEDS_REVIEW 即可 | 确定事实必须有证据；待核只作待核展示，不借标签输出无证据的确定结论 |
| 只修复或补“一次”模型纠错 | 累计尝试预算内复用原恢复机制，不在旧重试之上叠新重试 |
| 无实际耗时/成本收益就不合并 | 仅约束性能优化候选；安全/正确性缺陷以反例和不回退为准 |
| 旧价格标视频发布/观察时间 | 两者不可互换；created_at 更不是观察时间，显示来源时间的真实类型 |
| 多 Source 意味独立共识 | 技术来源数去重与来源独立性不同；转载不自动当多次实地证实 |
| 字符串不同即冲突 | 先比较对象、条件、单位和时间；缺信息标未知，不把条件差异当矛盾 |
| PREVIEW_ONLY / NEEDS_USER | 前者完整性，后者任务状态，分别建字段/映射，不新增混合终态 |
| 三点字幕抽样无误即考虑开启 | 三点不证明全篇一致；研究结果不能自动放松已冻结信任门禁 |
| CI 写好即可交付 / CI 必须真实运行 | 本地检查、workflow 静态验证、托管运行分层；无推送授权不启动远程，以 NOT_RUN 交付待验边界 |
| 通用模板禁止一切重启/发布 | 本次仍仅文档；未来明确前端实施遵循已有持续发布授权，迁移/真实调用/历史数据等仍独立 |
| 每次强制读 CURRENT_HANDOFF / 所有报告 | 按根 AGENTS 路由读取；生产信息不作为日常计划默认上下文 |

未采纳为默认实施：局部第二轮模型补提、自动确认阈值下调、字幕抽样替代全量 ASR、无条件新平台、大文件全面拆分。它们保留为有条件研究/候选，并非悄悄丢弃；启动条件分别写在 Q/P/S/X/执行契约。已有专项计划不因本次重编而自动归档，只有被实施覆盖后才按维护规则处理。
