# K｜多来源事实、条件与时间对照

返回[总览](README.md)，遵循[执行契约](09_AGENT_EXECUTION.md)。承接原 05；复用 aggregate_place_knowledge、PlaceDetailPage 与既有详情 API。已实现按 Source 去重及 observations，不再新建多视频聚合器。

## 实施阶段

1. **K1 定点审计。** 用同 Place 的 2–3 个独立来源及重复 Mention/Note 版本检查来源数、事实簇、条件/主体范围、删除与人工资料保留；没有真实材料则显式 Mock。当前 `_state` 把同 insight_type 的不同簇直接标冲突，只是需检查的线索；用“同地点不同季节/子景点/计价单位”等反例确定缺陷，不先重写聚合。
2. **K2 语义边界。** 同对象、同事实类型、相容条件/时间/计量单位下才能比较一致或矛盾；不同条件分别呈现，条件缺失为无法判断，不靠字符串不同或多数投票断言冲突。多个 Source 的内容也可能转载，独立 Source 数不等于多个独立现场验证；不凭计数提升事实置信度。聚合保留每条观察、原句、版本与个人备注，不用新 LLM 自动统一观点。
3. **K3 时间和展示。** 明确区分事实观察/发生时间、视频发布时间、记录入库时间。缺观察时间时可显示发布时间，但必须标“视频发布于”；仅有 created_at 只能写“收录于”，不能写“最新实测”或“当前有效”。旧票价/营业/排队仅是来源记录。优先在现有详情卡分组/展开证据，不建设并排决策台；“作者认为适合”不改成实时客观推荐。

## 验证与完成

入口 `services/{place_knowledge,place_experience,travel_brief,travel_timing}.py` 与详情 API；目标 `backend/tests/test_place_knowledge.py`、`test_place_retention.py` 及受影响前端测试。覆盖同义/不同单位、季节差异、子景点、条件不明、真矛盾、正负观点、重复来源、版本切换、共享地点、来源删除、人工备注和缺时间。

每条聚合事实可追溯至少一条具体 observation；关键少数负向和条件保留，同视频重复不加来源数；删除仅清专属衍生内容、共享与人工记录保留。GET 无模型/业务写入，按需批量查询，记录查询数与耗时避免 N+1。先测源数据/DTO，再测 PC/Mobile 展示并按持续授权发布。本包涉及已有未提交保留策略修复时先辨别归属，不能覆盖它们。无具体缺口可 NO_CHANGE 结项；不新增来源监测、知识图谱或旅行推荐引擎。
