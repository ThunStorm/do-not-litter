# U｜待处理入口与原位复核体验

返回[总览](README.md)，遵循[执行契约](09_AGENT_EXECUTION.md)。合并原 02 WP2 与原 04 全部工作；只增强 Tasks、Video Notes、Place Reviews 现有入口。受影响 Q/R/P 契约稳定即可启动，不要求其全部真实矩阵毕业。

## 阶段与接口

1. **U1 只读投影。** 建立问题来源表：Job/Step 失败或等待、Mention REVIEW/UNRESOLVED、Note 质量疑点、登录/素材缺失。定义稳定去重键（问题类型+权威对象 ID+版本/执行身份），一个问题多个入口只计一次，但一个任务可有多个问题。“待处理任务数”和“问题数”不能混用。分页列表的总数由同筛选的服务端聚合提供，不只数当前页，也不全库 N+1。缺少身份时标未知，不拼一个猜测的历史 ID。
2. **U2 页面交互。** Tasks 增加需要处理筛选/计数和具体动作；POI 卡展示原词、短原句、时间码、地址类别、原因与版本准确的返回笔记入口。版本已删除或无法精确定位时提示失效，不能静默跳最新版本。已有人工确认/拒绝、409 revision、墓碑、隐藏保护保留；同实体的选择和筛选上下文在返回后恢复。
3. **U3 一致性与可访问性。** 问题处理后刷新权威对象及相关计数，复用已有跨页通知/焦点刷新，不新增常驻高频轮询。后台冷却等待与需人工操作分开；只有明确额度错误才写“因额度暂停”，普通超时不能这样标。PARTIAL_SUCCESS 是合法终态，不能因待核 POI 把 Job 改为 FAILED，也不能通过 UI 清除警告伪造业务完成。

动作必须由后端现有能力/Replay Options 判断：显示按钮不是执行许可；跳转 GET 不重跑、生成、确认或更新历史。无需操作的质量提示不强塞到红色待办；无法操作显示原因，不制造空按钮。名称、地址和作者推荐态度彼此独立，确认位置不代表确认作者观点。

## 验证与出口

前端入口 `features/tasks/{TasksPage,TaskDetailPage,AICallDetails}.tsx`、`features/places/PlaceReviewCard.tsx`、视频候选和地图复核页；后端只定位列表/统计/详情 API 与 note_quality。开发前按需读[视觉规范](../../design/FRONTEND_VISUAL_DESIGN_SYSTEM.md)，复用统一组件、Token 和 Dropdown。

隔离 API/DB 验证：完成、仅 POI 待核、多问题、冷却重试、登录缺失、旧版本、删除、网络错、409 和人工确认；测试同问题去重、不同问题不合并、跨分页计数、刷新后消失和失效锚点。受影响页面在 1440/970 与 390px 用 Browser 检查键盘/焦点、菜单、跳转/返回、遮挡及相关 console。用固定任务测从列表到目标证据的步数，实施前冻结目标（默认不超过三次主操作，不含展开长证据），不只写“少量操作”。

通过条件：计数可追溯、无伪状态/伪完成、版本跳转正确、没有额外模型调用或持久复核队列。实际前端实施按持续授权完成保存点、隔离构建、发布与生产 Browser；生产确认/重跑不因页面验收获得授权，交互写入用隔离环境或拦截，生产核对只读/无业务写入部分。
