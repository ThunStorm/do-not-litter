# R｜失败恢复、成本口径与有效优化

返回[总览](README.md)，遵循[执行契约](09_AGENT_EXECUTION.md)。承接原 03；已有 JSON 恢复、分包、预算、REMOTE_ONLY 备用、LocalAiMux 冷却等待和精确缓存，先确认反例未被现有实现覆盖。

## 阶段

1. **R1 失败与成本账本。** 从已有脱敏审计/响应只读重放，按阶段区分截断、语法、Schema、证据不合法、429、超时、阶段时限、未派发冷却、缓存及 Replay。复用现有审计字段，缺失记 UNKNOWN，不先造一张重复日志表。路由模型与实际模型、执行位置、首答/修复/备用、缓存身份、尝试预算分别记录。原文 38 次/8 次 JSON 是特定历史样本数据，不视作现模型普遍失败率，引用报告时核对样本范围。
2. **R2 有反例的最小修复。** 复用现有 `json_recovery.py`/Gateway；截断与格式错误分流，不吞无效事实、猜 ID 或默认把非法容器变空列表。先修零调用边界；不得在既有纠错之上再加“一次重试”造成 Retry×Fallback×Chunk 放大。保留同一 Job 累计预算、hard deadline、路由限制、未派发不计用量以及成功块缓存。跨仓问题只登记兼容性证据，不直接修改 LocalAiMux。
3. **R3 可选成本候选与真实验收。** 一次只改一个高开销因素。固定模型、输入、配置、输出契约；冷缓存与热缓存分别对照，缓存命中不是模型首答成功。普通 HTTP 请求不具有永久会话记忆，Provider 前缀缓存需实际契约和计费证据。先跑离线质量，再申请有限配对实测；无预算先停在候选。完整 Provider/路由矩阵复用既有验收门禁，按本次影响切片执行，不把所有型号毕业设为修一个解析 Bug 的前提。

## 验收

入口 `ai/{gateway,json_recovery,request_compiler,budget,token_usage}.py`、`services/model_attempts.py` 和必要的 video_support；目标 `test_ai_gateway.py`、`test_ai_request_optimization.py`、`test_ground_map_list_recovery.py`、`test_note_input_budget.py`。覆盖 null/错容器、未知/越界引用、截断、429、重试失败、预算耗尽、取消、精确缓存、远程备用与禁止本地备用。先复用现有测试，新增只针对缺口。

实际发出、未派发、缓存、合成回放分列；Provider reported usage、估算 Token、费用分别记录，未知不能当 0。缓存折扣和思考 Token 未获上游证据则不推算为实际账单。墙钟与请求累计耗时分开，P50/P95 报样本量，小样本只作描述。质量不退化；性能候选只有同条件收益才启用。确定性正确性/安全修复不以必须省 Token 为准入条件，也不能为“必须更快”而拒绝必要修复。

本地推理取消仍有真实闭环缺口：若选中该问题，需分别核对客户端退出、锁/lease、进程/模型实际停止；Mock 不证明推理停止。另列目标真实实验，不默认重启生产或中止在途任务。最终交付本次错误分类、复现/修复清单、预算上限及未验矩阵；不重复实现统一 Gateway。
