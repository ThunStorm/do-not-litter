# 视频推荐时节、主题继承与封面信息提取方案

> 日期：2026-10-29。状态：P0–P2开发完成，P3目标真实阶段验收与隔离新版本完成；2026-10-30指定样本真实重跑完成（新笔记，非旧历史猜绑），扩大人工金标及语义验收仍待用户。范围：旅行视频的时间理解、地点归属、地图阅读与筛选，以及可选封面文字识别。本文依据本会话2026-10-28的只读诊断与解析复现；不是新的生产验收记录。最初编写时仅授权保存方案；2026-10-29追加实施请求。P1与冻结契约的差异已于本轮获用户明确确认，真实模型、历史更新与发布仍按各自边界执行。

## 1. 目标与核心决策

让系统理解“开场提出暑期避暑需求，随后逐个介绍目的地”的完整推荐关系。即使每个地点段落没有重复月份，也能显示有出处的“暑期避暑推荐”；明确月份、具体活动、天气提醒和局部不推荐条件分别保留。

实施顺序：P0补齐正文时间识别与证据链；P1建立有证据的推荐主题继承并统一地图投影；P2按需增加封面OCR及视觉模型兜底；P3在独立授权后验证真实样本并处理指定历史笔记。P0/P1不依赖封面理解完成。

“暑假”保留假期语义，不机械映射为整个7—8月或6—8月；“避暑”是出行目的，单独出现时不生成月份。片头“每年7月15日到8月15日游客最多、最热”属于需求背景，不直接成为所有地点的最佳日期。明确的封面“8月份目的地推荐”可作为独立推荐主题证据，不能冒充正文原句或最佳观赏期。

## 3. 证据与语义契约

### 3.1 分离事实、推荐背景与地点投影

| 层次 | 内容 | 保存与展示原则 |
| --- | --- | --- |
| 证据来源 | 正式标题、转写连续原句、封面原图文字 | 保存原文、来源身份及版本；转写有Segment，封面有图片哈希与文字区域，标题不造Segment |
| 时间语义 | 时间表达、精度、用途、活动、历史/周期性、肯定/否定及条件 | 按原文保真；背景统计、旅行记录、推荐、限制分别表达 |
| 推荐主题 | 暑期避暑、8月目的地等作者主题及其适用范围 | 记录主题原句和覆盖的ContentUnit，不假设全片只有一个主题 |
| 地点应用 | 某地点为何适用某主题、有哪些局部补充或例外 | 显式记录主题到地点的关联依据，不按共享Segment广播 |

拟新增版本化的`temporal_contexts`与`temporal_applications`，先评估保存于GroundedMapArtifact既有JSON扩展；不是当前已支持字段。推荐最小字段：context_id、source_kind、evidence_refs、raw_time_text、precision、purpose、activity、scope、applicable_unit_ids、interpretation_status；关联包含entity_id、context_id、relation、supporting_evidence、exclusions和验证状态。模型自报置信度仅供观察，不替代证据校验。

命名建议：转写原句保持SOURCE_FACT；标题沿用TITLE_METADATA/TITLE_CONTEXT；封面使用独立COVER_TEXT；主题继承使用独立THEME_CONTEXT投影，不能伪装成地点正文事实。需同步DTO/导出/校验的来源枚举；跨模态主题来源仍可区分。没有可追溯关系则保留待核，不生成推荐月份。

### 3.2 继承资格与冲突

1. 识别作者正在提出推荐清单或主题，保存包含推荐意图的连续证据；仅出现月份、温度或“避暑”不够。
2. 明确后续ContentUnit属于该主题，包括跨分块的连续推荐关系。PRIMARY/SECONDARY且确属推荐对象可继承；OPTIONAL仅在被主题明确覆盖时保留“可选”，不升级整体推荐。REFERENCE、CONTEXT、中转、比较背景、用户拒绝和整体不推荐对象不继承正向推荐。
3. 范围限定在同视频、同转写及同Note版本。区域为推荐主体时直接挂到Destination；子景点需证明是该主题下的推荐内容，不因地理包含关系自动继承。路线中的经过节点同样不自动继承。
4. 只有同主体、同用途、重叠时间的事实才判定冲突。夏季避暑与秋季赏叶可以共存；夏季看不到雪限制观雪，不取消整体夏季游览；草原8月中旬后不推荐限制相关草原，不能推广为阿尔山整体不推荐。
5. 地点正文的具体限制约束继承结果；无法确定适用对象或指代时列为待核。封面与正文的明确冲突保留双方证据，不以最后出现或多数票覆盖。

冻结契约当前要求背景零推荐加权、共同景观只继承粗季节。P1提出的是“作者明确推荐主题”的新关系，必须在实施前确认并修订相关契约；历史气候/客流背景和既有SEMANTIC_CONTEXT仍不加推荐分，不能以新增主题关系绕过原规则。

## 4. P0：正文识别与证据归属修复

- 统一TEMPORAL_CUE、has_temporal_scope、日历解析与展示层识别的时间词集合；覆盖春夏秋冬、暑假/寒假/盛夏、月份和跨年、日期范围、旬段、相对时段。假期不可强行填season/month，必要时新增语义类型与原词展示。
- 修复“月份”“宝藏”“到底”等标题修饰词误作范围条件。范围优先从有依据的地理、活动与主题约束产生，不把所有残余字串当必须逐字命中的地名；保留真正的“川西赏花”等范围约束。
- 按Claim明确主体读取其完整连续证据，校验同Snapshot/版本、Segment顺序、原句和对象。可在新产物中为Claim保留独立证据引用，不必把所有Claim片段无差别并入Mention。无效主体和跨地点歧义不降级为广播。
- 跨句恢复只能使用有归属证据的相邻片段；历史统计的时间修饰词必须随完整句保留，避免截掉“去年”后变成年度推荐。
- 时间状态区分HAS_LOCAL_TIME、HAS_THEME_CONTEXT、TIME_UNRESOLVED、NO_LOCAL_TIME、NOT_ANALYZED；可用DTO归一化旧状态。没有窗口不等于作者没提过时间，旧ANALYZED也不等于已完整理解。

完成条件：古龙山完整原句产生“夏天漂流体验较好”的活动级时间信息；暑假可被识别但不伪造月份；8月客流统计仍为背景；标题修饰词不造成误拒绝。

## 5. P1：推荐主题提取、版本绑定与地图一致性

复用现有GROUND_MAP调用提取主题及其适用关系，不默认增加独立LLM阶段。先定位前言、主题切换和结语等候选段，将经程序验证的原句作为有界主题上下文提供给相关分块。跨块引用需专用来源注册表和可还原短ID；主题证据必须随请求提供，不能引用模型未见过的Segment或依赖会话记忆。主题过多时按适用范围分配，不静默丢弃。

后处理校验context/entity/unit引用、逐字证据、跨块还原、适用关系及局部例外。Prompt、提取Schema、主题解析器和投影版本进入Artifact身份；新旧结构不能错误共用结果缓存。NOTE_REDUCE接收已验证的地点时间投影，保留来源类型，不重复独立判断时节。

新产物与Note版本固定关联；Place及Destination共享一套有效时间计算，避免仅PlaceVisitWindow支持地点、行政区域丢失时间。建议先通过版本化只读投影返回统一DTO，不在GET中补写历史窗口。若现有JSON/索引不足而必须新增Schema，另建Alembic迁移并单独评估发布。

地图浮窗、地点/区域详情、月份筛选、季节筛选、聚合和导出均消费同一投影，显示与匹配不可各写一套规则：

| 证据结果 | 默认展示 | 筛选规则 |
| --- | --- | --- |
| 仅暑期主题 | 暑期避暑推荐；来源可展开 | 匹配暑期/避暑语义；不自动匹配精确8月筛选 |
| 经核验的8月主题且地点适用 | 8月推荐目的地；注明主题来源 | 可匹配8月推荐；保留局部日期/条件 |
| 7月15日至8月15日炎热与出行高峰 | 推荐背景中保留原句 | 不作为目的地最佳日期或推荐筛选依据 |
| 去年8月气温/客流 | 历史参考 | 不进入推荐月份匹配或加权 |
| 8月中旬以后不推荐某草原 | 明确保留后半月限制 | 月级结果标有条件，禁止显示为整月适宜；有明确日期查询时按证据匹配，不把中旬捏造成15日 |
| 尚无有效归属 | 暂未提取到该地点的时节依据 | 不宣称全年适宜，不武断声称视频没有说明 |

默认阅读主文简洁，来源详情能跳转Note/时间码或封面文字区域。继承范围、天气提醒和作者意见不伪装为系统旅游保证。涉及前端时按设计系统实施并验收PC/Mobile。

## 6. P2：封面文字与视觉模型

结论：支持封面补充值得做，但不作为P0/P1的前置依赖。样本正文已证明暑期主题；封面的增量是明确8月。仅凭山水、雪景、衣着等画面不能推导最佳月份或地点身份。

默认流程建议：已有受控本地封面 → 本地OCR → 文字区域/阅读顺序/月份与否定词质量检查 → 合格文字进入主题解析；OCR低可信、文字重叠、多个时间候选或主次关系不明时，按配置使用视觉模型兜底。OCR引擎选型需先核对本机可用能力、安装成本与样本效果，本文不预设已安装或已验证。无可用模型时保留待核，继续正文流程。

视觉调用只负责提取可见文字、区域及主次关系，输出独立结构；其语义应用仍经过第3节校验。封面及OCR文本均为不可信来源数据，图片里的指令不能改变系统守卫、调用工具或跳过证据检查。使用原图或保留文字可辨性的版本，优先一张封面一次兜底，不扩展为逐帧理解。

现有VISION_FACT与视觉能力校验可复用Gateway基础设施，但封面不是截图：新增独立的封面提取任务/阶段配置、产物身份和失败状态，长任务进入Worker。复用截止时间、预算、取消、串行限流和审计；视觉资料发往真实Provider仍需独立授权。默认关闭真实视觉兜底，开启后也只按需触发。

缓存键至少包含封面字节哈希、OCR引擎/版本、预处理版本；视觉结果另含Provider/Profile、模型、Prompt/Schema及有效参数身份。封面内容或审核状态改变须影响下游主题输入哈希。失败缓存应有期限，新增可信结果生成新版本，不静默替换旧证据；每条路径记录耗时、费用/Token可观测值或UNKNOWN。

评估采用同一小样本集比较正文基线、正文+OCR、正文+视觉三组，覆盖明确月份、大字与装饰字、多月份、否定、冲突、模糊图和无文字封面。人工标注文字、时间语义和适用范围，记录月份准确率、否定保留率、错误继承、召回增量、兜底率、时延与成本。先排除严重误继承，再据实际增益决定是否扩大启用；本方案不声称视觉优于OCR或给出未测成本。

## 8. 验收矩阵与验证顺序

| 编号 | 用例 | 必须满足 |
| --- | --- | --- |
| T01 | 本视频无封面识别 | 暑期主题可覆盖已证实属于推荐清单的地点，抓喜秀龙不再显示视频未说明时节 |
| T02 | 片头7月15日—8月15日 | 保留需求背景，不能生成全地点最佳日期 |
| T03 | 古龙山跨Segment | 夏季漂流体验有完整可定位证据；不能凭此推导全年或具体8月 |
| T04 | 通灵客流/往年气温 | 可读历史参考，不加推荐分、不污染推荐筛选 |
| T05 | 草原中旬后限制 | 日期方向和局部对象保留；不扩大到整座城市、不写成整月推荐 |
| T06 | 暑假、寒假、四季与月份修饰 | 表达识别一致；假期不猜月份，“月份宝藏”不造成范围误拒绝 |
| T07 | 多主题、比较/中转、否定地点 | 不跨主题或错误对象继承；不产生POI确认 |
| T08 | 多分块/指代/非法引用 | 有界上下文可验证还原；跳段、无效主体和歧义保留待核 |
| T09 | 同主体不同用途 | 避暑、赏叶、观雪、道路安全彼此独立，真实限制不丢失 |
| T10 | Place与Destination | 同源时间语义一致；详情、筛选、聚合、导出一致 |
| T11 | 封面OCR/视觉失败或冲突 | 不阻塞正文；否定不丢失，冲突可见，证据来源正确 |
| T12 | 缓存与历史版本 | 图片/Prompt/解析变化影响身份；旧版NULL不猜绑，普通GET无回写 |
| T13 | 手工信息及来源冲突 | 人工窗口保留；不同来源不能错误合并为共识或覆盖 |

先用已保存的真实证据制作脱敏且保留出处的离线fixture，人工确认预期关系；不得把当前模型输出直接当金标。开发先跑目标后端/前端检查，完整代码包只跑一次全量验证，保留云南P0_CRITICAL。前端变动需PC/Mobile Browser，模拟写请求不得写入生产。真实GROUND_MAP/封面模型测试单独授权、串行执行并记录请求与Token；离线函数通过不代表模型提取质量或真实端到端通过。

## 9. 历史处理、发布与文档落点

先生成指定Note的只读差异：旧/新时间原词、来源、对象、用途、继承/拒绝原因、匹配变化及冲突；不把“未生成窗口”统一认定为缺失。对缺固定Artifact引用的旧版，以授权的新解析/新Note版本建立可追溯绑定，不能更新旧产物或猜绑。纯规则可用既存证据时优先离线重算；缺少新主题结构时说明需要重新提取及成本，真实调用另外授权。

获准实施后先冻结P0/P1验收与契约变更，再开发；P2可独立后置。发布按仓库门禁保存源码/静态回退点；涉及API/Worker重载须空闲与已验备份，迁移独立授权。旧Note/窗口、人工补充和POI状态保留，当前版本切换须可恢复；发布新代码不等于授权批量历史重算。
