# 后续工作包 M3 · 已发出请求的首包超时备用恢复

2026-11-06 · 后续候选，独立实施与验收。依赖[本期 M1/M2](LOCALMUX_FIRST_PAYLOAD_AND_COOLDOWN_PLAN.md)的结构化错误契约。本期验收不依赖 M3。

「12月份最有氛围感的宝藏目的地推荐」的同一抽取分块两次使用相同输入哈希并触发 Qoder 首包超时。已经发出的请求即使没有首包，实际执行和计费仍未知。M3 让配置了合格备用模型的任务能恢复这类分块，沿用现有阶段主备策略和尝试预算。

- **触发。** 首包超时由 M1 的结构化原因确认，且同一 Job、阶段、主模型和逻辑分块输入有两次独立的、已发出的首包超时证据。使用已有审计确认，兼容缺少新字段的旧记录，历史通用 502 不自动当成命中。仅为了凑到触发次数，不自动再发一次主模型请求。
- **路由。** 复用现有主备切换、配置快照和能力门禁。只选用户已启用、能力匹配、策略允许且不共用故障连接的备用模型，按备用自己的参数、凭据、并发和配额约束执行。一次恢复最多调用备用一次，计入现有阶段预算，保持原任务证据和缓存身份，审计标明主备用量及切换原因。
- **停止条件。** 无合格备用、连接归属无法核实、预算不足或备用失败时，保留原失败证据并交给用户处理。保持主模型既有重试边界。首包超时不作为输入超限或输出截断的证据，不触发自动拆包或模型输出经验调整。
- **独立验收。** 使用合成响应验证两次确认超时、不同连接、合格备用、预算充足时恰好一次备用调用。单次超时、通用 502、同连接备用、未授权、能力不匹配、额度不足和备用再失败都要有相应的停止证据。真实模型切换、质量与用量另行授权验证。
