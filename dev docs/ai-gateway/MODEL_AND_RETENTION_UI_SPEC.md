# 至简 模型配置与历史清理规格

版本：v0.4，更新日期：2026-08-21，状态：`IMPLEMENTED / BROWSER_VERIFIED`。适用部署：Mac mini 单节点。

## 1. 自定义模型库与路由

模型设置不再固定展示 DeepSeek、MiMo、Ollama 等预置槽位。用户可新增、编辑、真实测试并保存任意 OpenAI 兼容或 Ollama 模型配置；每条配置至少包括显示名称、Provider 标识、Base URL、模型名、超时、可选调用间隔和 API Key。调用间隔以秒为单位，留空继承通用设置；主模型与备用模型按各自 Profile 的值等待。API Key 只进入 macOS Keychain，接口和 SQLite 仅返回“已保存/未保存”状态。

“推理路由”独立于模型编辑：主模型与备用模型均从已保存的模型库中选择。转写校对另有可选的主/备用模型，两项均优先于推理路由，对应项留空时分别继承推理主/备用模型。主模型是唯一默认调用目标；仅在网络、HTTP、超时或 Provider 不可用等可恢复调用错误发生时才尝试备用模型。备用模型可留空；所有有效路由都未选择主模型时，依赖模型的任务必须进入 `NEEDS_USER`，不得回退到硬编码模型。

已被主/备用路由引用的模型不能删除；先切换路由才能删除。每次保存、路由切换、真实测试、自动备用切换和删除均写入审计日志，不含 Key。

### 1.1 已保存模型测试队列（2026-10-11）

“已保存模型”栏提供“一键测试全部”，逐模型先做真实连通测试，再做能力探测；连通失败不继续调用该模型，其他模型独立继续。单模型的真实测试/能力探测共用同一队列，重复提交已在排队或运行的同项任务复用原Job，BOTH覆盖TEST/PROBE；完成后再次点击是新的测试。界面显示本次批量进度与逐模型排队/执行/完成/失败/取消状态，可单独取消；进行中的模型禁止保存、删除或读接口，未保存编辑不会因探测结果刷新而丢失。PC与390px使用既有按钮/反馈体系，无横向溢出。

已保存模型的界面测试通过`POST /api/settings/model-tests`立即入队，由Worker独立最多三线程执行`MODEL_TEST` Job，视频/招聘处理通道不领取这些Job，普通任务列表/首页近期任务及状态计数不混入测试记录。复用既有测试/探测处理函数的结果写入与脱敏逻辑；每个测试有独立Session、续租和执行fence，晚结果不能覆盖新执行。Job只保存Profile ID、身份哈希、不可逆分组哈希和结果，不保存凭据。

同一入口（scheme/host/port，忽略路径）或同一明确命名的供应商串行FIFO；通用OpenAI兼容/LocalAiMux是协议或桥接名称，不把不同入口误合为一个供应商。Worker调度跳过被占用的分组但保留冲突任务先后，独立分组可并行；跨API/Worker使用同分组文件锁，整段探测持锁，本地模型不论直连模式、Provider或入口都共用硬件串行/keep_alive=0；每次真实测试或探测子调用结束（成功或失败）后至少5秒再开始下一次，间隔/RPM要求更长则取更长值。完成时间与等待期限写入共享锁文件，跨模型/API/Worker保留；不因Base URL缺失或切换模型跳过等待。已保存与草稿探测先取分组锁再取硬件锁，避免反向取锁互相等待。远程每请求至少4秒并尊重Profile间隔/RPM，HTTP429或额度/限流错误按Retry-After且至少60秒共享冷却，不自动重试、换Key或备用。外部账户额度和其他应用流量不能由本队列保证；失败原因单独呈现，业务小样结果不代表全面质量。

既有同步test/probe及草稿接口保留兼容，使用同一分组锁/节流，手动测试不改变生产熔断。草稿仍不持久化Key。一键测试仅在用户显式点击时创建任务，Worker启动/页面刷新不自动测试。回归入口：`backend/tests/test_model_test_queue.py`；界面截图及隔离验收用模拟模型，不替代真实Provider验收。

## 2. 历史删除

任务列表与内容列表提供独立的“删除历史”入口。删除不是归档：操作需要确认，成功后列表立即移除并写审计事件。

- 仅 `COMPLETED`、`PARTIAL_SUCCESS`、`FAILED`、`CANCELLED`、`NEEDS_USER` 状态的任务可以删除；排队或运行中任务必须先取消，防止 Worker 写入已删除记录。
- 删除任务会级联删除其步骤和执行事件；已生成内容不会被连带删除，用户可在内容页单独判断是否删除。
- 删除内容会删除该内容及其专属 Claim/Evidence；若同一 Source 已无其他内容、视频笔记或活跃 Job，则同步删除其来源审计记录、Snapshot/Segment 与专属视频资产。Place、路线和已独立持久化的地点信息保留。
- 来源审计页支持手动删除孤立 Source；存在内容、视频笔记、排队/运行任务或取消清理 lease 时返回 409，并显示各类阻塞数量。
- 前端确认文案必须说明上述边界；操作成功后刷新任务/内容/待办/概览缓存。

### 2.1 视频完整转写 180 天自动清理（已实施）

视频完整转写采用固定 180 天保留期，不复用当前通用 `data_retention_days`/日志保留配置，也不增加可变的用户设置。保留截止时间从 Transcript 创建时计算，并显示在视频 AI 笔记页；有效期内可导出完整时间码 TXT。

Worker 启动时及最多每 24 小时执行幂等清理：正文、Segment 文本、Evidence quote 和 metadata 全文 fingerprint 被物理清空，保留 Transcript ID、版本、哈希、时间码元数据、`retention_until/purged_at`、AI Note 与截图。过期后页面显示“完整转写已按 180 天策略删除”，导出和完整转写接口返回 410。浏览器已下载到用户设备的文件不受服务端清理控制。

### 2.2 视频笔记删除（已实施，v0.4.6 更新）

视频笔记列表和详情均在 `…` 菜单提供“删除笔记”，共用 `DELETE /api/video-notes/{note_id}`。删除 AINote、版本、Section、TOC 和 Content 投影；若 Source 已无其他内容或活跃 Job，再清理 Source、VideoAsset、CoverAsset、Transcript、截图与 Segment Evidence。Place、路线及独立地点信息保留。活跃生成 Job 阻止删除，第一版不提供回收站。

## 3. 页面与响应式

模型页先显示“推理路由”两条选择框与状态摘要，随后是可展开的“已保存模型”列表和“新增自定义模型”入口。窄桌面下路由选择框垂直排布，编辑卡仍使用既有暖白、朱砂红与细线体系，不引入第三方品牌图标。

### 3.1 已保存模型的独立折叠（2026-10-12）

“已保存模型”是模型列表的父区块：一个有标题的 section 同时包含标题操作栏、测试说明/批量反馈、模型列表、新增表单及空态；外层边界包住整个列表，子卡片内缩并使用既有 muted surface 与柔和边框表达层级。每个已保存模型默认收起，保留显示名称、精确模型名、路由使用标记、测试状态和既有操作入口；共享 IconButton 提供独立展开/收起，支持键盘及 `aria-expanded/aria-controls`。折叠仅隐藏表单，不清空未保存编辑或停止测试轮询；新增配置默认展开。PC/390px 均须无横向溢出，展开一个模型不影响其他模型。

### 3.2 模型名下拉与目录刷新（2026-10-12）

模型名使用可搜索的共享 SelectMenu，可从当前值/预置候选或手动刷新的服务目录选择，并保留独立的“手动填写”。刷新不会自动换模型、修改路由或保存配置；目录缺少当前模型时明确提示并保留原值。目录响应只适用于提交时的服务来源、地址、接入方式及填写凭据，连接变化或过期响应不会覆盖新选择。长模型名在按钮中截断、在列表中换行，PC/390px不得撑宽页面。

`POST /api/settings/model-catalog` 接受当前连接草稿与可选 `profile_id`，不要求先选定模型；只读取元数据，没有推理、任务或探测调用。已保存模型留空Key时从Secret Store读取；服务来源或地址origin变化后不得复用旧Key，须填写新连接凭据。返回精确 `models[].id` 与采样时间，不返回Key或完整上游元数据，只审计Profile ID及模型数量。页面不自动刷新，不把目录存在当作业务能力通过；短期结果只保留在页面内，不写localStorage或SQLite配置。

| 连接 | 目录入口 | 已核对的来源 |
| --- | --- | --- |
| DeepSeek 直连 | `GET /models` | [官方模型目录文档](https://api-docs.deepseek.com/api/list-models/) |
| OpenRouter | `GET /api/v1/models` | [官方模型目录文档](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties) |
| Ollama | `GET /api/tags`，列出已安装模型 | [官方目录文档](https://docs.ollama.com/api/tags) |
| LocalAiMux | `GET /v1/models` + `GET /api/chat/models` | `ai/model_catalog.py` 校验两个目录的实际模型ID一致；仅忽略标准目录中 owned_by=localmux 且ID为 free/cheap/balanced/best 的虚拟路由，选择器返回实际模型；逐模型能力复用同一校验 |

后端连接等待上限5秒、读取等待上限20秒、整个读取期限30秒；第二次HTTP等待按剩余总预算收紧，响应上限1MB/1000条，拒绝重复/非法ID、凭据反射、不含凭据的地址校验失败及Mux目录不一致；不跟随重定向、不使用环境代理、不自动重试。超时、HTTP状态错误、实际模型目录不一致与其他异常响应分别返回脱敏错误，保留原模型并允许手动填写。2026-10-12只读采样：Mux冷标准目录10.16秒、随后能力目录0.03秒，两者56个实际ID一致；原5秒读取上限不足。源码修复与部署后现场验收分别记录，不能以离线样例代替。回归入口：`backend/tests/test_model_catalog.py`、`frontend/src/components/ui/SelectMenu.test.tsx`；Browser涵盖选择/搜索/刷新、失败保留、连接变更、手动填写和超长模型名。

任务与内容行的删除入口默认隐藏于行尾操作区；窄桌面保留最小 40×40px 触控区域，删除前使用原生确认对话框并附带对象名称。删除控件不得覆盖行的详情跳转区域。

## 4. API 契约与验收

模型库接口：`GET/POST /api/settings/model-profiles`、`PUT/DELETE /api/settings/model-profiles/{id}`、`POST /api/settings/model-profiles/{id}/test`；通用/转写路由：`GET/PUT /api/settings/model-routing`；转写参数：`GET/PUT /api/settings/transcript-processing`。任务删除：`DELETE /api/jobs/{id}`；内容删除：`DELETE /api/content/{id}`；孤立来源删除：`DELETE /api/sources/{id}`。

验收：新增两个自定义模型后，可分别选为主/备用；已被引用模型无法删除；主模型连接失败时视频笔记记录实际备用模型并写入审计；没有主模型时任务明确需配置。终态任务和内容均可删除，运行中任务返回可理解的冲突提示，删除后刷新不再出现且相关审计日志可查询。

### 系统指令传递探测（2026-10-14）

已保存模型的“读取接口能力并探测”先只读接口目录，再将独立系统指令传递小样提交到现有 Worker 队列（INTERFACE）；不在目录读取 HTTP 请求中执行推理。模型、地址、接入方式或凭据未保存时只读目录并提示先保存；新模型草稿同样不自动调用已保存的其他配置。保存时的目录核对仍为只读，不自动探测。按钮会真实调用模型，说明文案须明确。

普通能力探测也包含 SYSTEM_INSTRUCTION 小样。小样使用合成 system 规则与冲突 user 请求，只有精确匹配 system 内随机标记才 PASS；不符合规则为 FAIL，请求未完成为 NOT_TESTED，附脱敏错误码。未知目录允许在独立小样临时发送 system，不修改上游目录声明或正式 Stage 门禁，也不授予业务能力。结果在折叠卡原测试反馈处展示“系统指令传递小样：通过／未通过／未验证／未测试／探测中”，同时展示目录声明和小样理由。未知与未测使用中性颜色。结果含模型、采样时间及接口指纹；配置/凭据变化清除旧结果，执行期间配置变化拒绝保存。沿用串行、间隔、去重及取消；不把小样通过描述为原生 system 优先级验收。
